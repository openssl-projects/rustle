## Selecting the provider

All algorithms are registered with the property `provider=bc_rust`. A fetch
can require this provider with `-propquery "provider=bc_rust"`. The optional
form, `-propquery "?provider=bc_rust"`, prefers it but allows another provider
to satisfy the fetch.

The colon-separated names in each row are aliases for the same implementation,
including its object identifier where listed. The algorithm name identifies
the hash; the property query selects which provider supplies it.

## Algorithm registration

OpenSSL asks a provider for algorithms by operation type. This provider's
digest table is the `DIGESTS` static in `bc-rust-provider`, exposed through
`ProviderDesc::digests`. Each entry associates its names and properties with
the opaque `DigestFunctions` table generated by
`DigestAlgorithm::<H>::functions()` for that digest context type.

The table keeps every callback tied to the same context type. This matters
because creating a context with one implementation and updating or freeing it
with another would be invalid, even if their C callback signatures matched.
Provider code selects a complete table rather than assembling callbacks from
different implementations.

Method presence decides which optional callbacks each table contains. An
operation is advertised only when the digest implementation supplies its
method; a default Rust method alone does not establish support. See
[Vtable](./design-vtable.md) for how this relationship works.

## Supported behavior

All listed digests support streaming, context duplication, context copying,
and state serialization where supported by OpenSSL. These fixed-length hashes
have no configurable context parameters, so they register context parameters
in neither direction, matching the default provider's fixed-length digest
interface. Digest and block sizes are algorithm-wide properties, not settings
of an individual computation. The Crate Split explains this
[parameter distinction](./design-split.md#algorithm-properties-and-context-parameters)
and the [state compatibility policy](./design-split.md#digest-state).

Other OpenSSL operation types are not currently supported.
